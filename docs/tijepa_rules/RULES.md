# TiJepa rules carried into GeneWorld

Copied verbatim from the TiJepa repository (rafidquadir-eng/TiJepa, branch tijepa-v3). They apply to GeneWorld unless GeneWorld's own plan says otherwise.

## From PLAN.md

## 1. Rules (non-negotiable)

### 1.1 Scientific integrity
1. **No fabricated results.** Every number, table, and figure in `paper/` must be generated by code
   in this repo from data actually downloaded in this run, and must trace to a file in `results/`.
   Numbers in the manuscript are filled by `scripts/make_paper_numbers.py` from `results/*.json` —
   never typed by hand.
2. **No synthetic or simulated data presented as real.** Synthetic data is allowed only inside
   `tests/` for unit tests and must be named `synthetic_*`.
3. **No fake pairings.** Images and omics from different studies are never presented as matched
   samples. Part C is explicitly a condition-level, cross-study, cross-species *bridge*, labelled
   as hypothesis-generating everywhere it appears (abstract, results, figure legends).
4. **Null and negative results are reported**, not dropped. If TiJepa does not beat a baseline,
   the paper says so.
5. **Leakage control.** All evaluation splits are grouped by the highest available biological /
   technical unit (batch > animal/donor > movie > field of view > cell). Never split at the
   cell or frame level when a higher grouping exists.
6. **Claims allowed:** "self-supervised video representations of innate immune *activation /
   polarization*", "signalling dynamics predict features of *LPS tolerance*", "projected position
   of trained/tolerant states (hypothesis)". **Claims not allowed:** that TiJepa or iMEMORY
   *identifies trained immunity from images*; any claim implying imaging of trained cells was
   performed; any claim about human disease, lupus, or patients.
7. **iMEMORY.** Do not access, request, or reference any private or partner data (Mount Sinai,
   Columbia, Broad, or iMEMORY patient data). The Discussion may say the learned representation is
   designed to be added to multi-omic models such as iMEMORY as future work — nothing more.

### 1.2 Licences
1. **Pretraining data:** only CC0, CC BY, or MIT/BSD licensed data (Section 4 lists them).
2. **Excluded entirely:** Zenodo `10.5281/zenodo.16319732` (CC BY-NC-ND), DeepCell
   DynamicNuclearNet, the Cellpose *training set*, CTMC-v1, LIVECell (licence unresolved),
   Cell Tracking Challenge data (no stated licence).
3. **Third-party model weights** (DINOv2, V-JEPA, Cellpose models, CoTracker, etc.): record the
   licence of each in `manifests/models.yaml`. Non-commercial weights are acceptable for this
   non-commercial preprint **only** if the paper's Methods states the licence. Prefer permissive.
4. Record every dataset's verified licence (read from the record itself, not from this plan) in
   `manifests/datasets.yaml`. If the record's licence differs from this plan, the record wins.
5. Repo licence: add `LICENSE` = **Apache-2.0** for code and `LICENSE-docs` = **CC BY 4.0** for
   text/figures. `TODO(author)` note in the PR if a non-commercial licence is preferred.

### 1.3 Repository hygiene
1. Work on branch `tijepa-v0`. Commit at each milestone (Section 9). Push regularly. Open one PR
   to `main` at the end. **Never** force-push, rewrite history, or push to `main` directly.
2. Raw data, caches, checkpoints, and large arrays stay out of git (`.gitignore` already covers
   `data/`, `checkpoints/`, `*.pt`, `*.tif`, `*.zarr/`, etc.). Keep all raw/processed data under
   `data/` and all checkpoints under `checkpoints/`. Committed result files must be < 5 MB each.
3. Put manifests in `manifests/` (not `data/`, which is gitignored).
4. Downloaded files are untrusted: extract archives into their own directory, never execute code
   shipped inside a dataset, run Python that reads them with `-I` where practical.

### 1.4 Authorship and disclosure
1. Sole author: Rafid Quadir. Do not invent co-authors, affiliations, funding, or acknowledgements.
2. Include in the paper: *"Code, analyses and an initial manuscript draft were produced with the
   assistance of an AI coding agent (Claude, Anthropic) under the author's direction; the author
   reviewed and is responsible for all content."* Mark `TODO(author): review`.
3. **Do not submit or post anything** to bioRxiv, Zenodo, Hugging Face, or social media. The
   author does that after review.

## From PLAN_v1.md

## 1. Rules

All of `PLAN.md` §1 remains in force (integrity, licences, hygiene, authorship). Additions:

1. **Data-type guard.** Every omics matrix is checked on load: row-ID pattern (gene symbol /
   Ensembl ID vs genomic interval `chrN.start.end` / `chrN:start-end`), sample count against
   the GEO series, and assay type against GEO `library_strategy`. A mismatch is a hard error.
   This is how the v0 ATAC-as-RNA bug must never recur.
2. **Sanity checks before results.** Every differential-expression or signature step must
   first pass a positive control (Section 7.1). A pipeline that fails its positive control
   produces no reported result; the failure is reported instead.
3. **No CIs from fewer than 10 groups.** With < 10 grouping units, report per-group values,
   the exact permutation distribution and the minimum achievable p, not a bootstrap CI.
4. **Seeds must vary something.** Any "mean ± sd over seeds" must come from runs that differ
   in a real source of randomness (pretraining init, random-init draw, cell subsample, fold
   assignment). If sd is exactly 0, the seed claim is removed.
5. **Prose follows numbers.** Directional words in the paper ("higher", "beats", "worse",
   "indistinguishable") are generated from CIs by code (Section 10.2). Hand-written
   directional claims are forbidden.
6. **Google Drive is the author's private storage** and is authorised for backups. It is not
   "posting". Never print, log, or commit rclone config, tokens, or credentials.
7. **The circular "reduced one-axis" analysis is deleted** from code, results and paper.

## From PLAN_v2.md

## 1. Rules (in addition to PLAN.md §1 and PLAN_v1.md §1)

1. **Provenance guard.** Every encoder result records the checkpoint file, run name, step and
   SHA-256 it came from. Paper and figure labels are derived from that record, never from a
   hand-written map. A results file whose checkpoint does not match its label is a hard error
   (this is how N1 must never recur).
2. **Nothing is generated before its inputs exist.** Paper, figures and run report are
   regenerated only after pretraining and all evaluations have finished. If an analysis is
   absent, its section says so in one sentence; no placeholder sections.
3. **Single writer on shared storage.** Exactly one process may write a given checkpoint. The
   trainer takes an exclusive lock file (`checkpoints/<run>.lock`, holding hostname, PID,
   start time) and refuses to start if a live lock exists. Checkpoints are written atomically
   (`tmp` file + `fsync` + `os.replace`).
4. **Budget is defined in steps, not wall-clock.** The LR and EMA schedules must anneal fully
   by the last step of every run.
5. **No internal process language in the manuscript.** No review-finding IDs (D1, N3…), plan
   section numbers, "v0/v1/previous version" narrative, file paths into `results/`, or status
   strings in the paper body or figure titles. Version history belongs in
   `reports/V0_ERRATA.md` and one sentence in Methods.
6. **Expected biological directions must be sourced.** Any "as predicted" or "expected
   direction" in Part C cites the publication and the specific result it comes from; otherwise
   no expectation is stated.

## From PLAN_v3.md

## 1. Rules (in addition to PLAN_v2 §1, PLAN_v1 §1, PLAN.md §1)

1. **Selection is never done on reported test sets.** Recipe choices (H3) are made on
   validation data that never appears in a reported result (H3.1). Every reported number
   comes from a model frozen before its test set was touched.
2. **Decision gates are binding** (§2). If a gate fails, take the branch the gate names;
   do not run the more expensive step "to see".
3. **Keep training snapshots.** Any new training run keeps immutable snapshots at every
   10,000 steps (`checkpoints/<run>/step_XXXXXX.pt`), in addition to the rolling resume
   checkpoint.
4. **Cost hygiene.** No background loop may run on the GPU instance once its purpose is
   done (the v2 pretrain monitor is still writing rows at step 117,000 every 2 h). When the
   GPU will be idle for > 2 h, say so in the PR body so the author can stop the instance.
5. **Backups are part of "done".** A milestone that produces a checkpoint is not complete
   until the checkpoint exists in a second, persistent location with a verified hash.
